Three things to try

  1. Step one binary search. At the start (binary · 12, vin = +0.1234 V), press Step twelve times: each decision moves the DAC by half the previous step (1024, 512, 256 … 0.50 LSB), and the conversion ends at code 2553, ideal 2553, error 0 LSB.
  2. Let noise flip a decision. Set vin to +0.1255 V, where decision 2 leaves a residue of only 2.05 LSB, switch on Noisy fast decisions and press Run a few times. In about three runs in ten, decision 3 turns red and the code ends at 2559, error −3 LSB: the binary steps still to come add up to 255.5 LSB, less than the 256 LSB step just taken, so they cannot undo it.
  3. Count the damage. With the noise still on, press Convert 1000 inputs: the binary search is off by more than 1 LSB for roughly 8–10 % of inputs (rms error 1.0–1.2 LSB, against 0.29 LSB noise-free), while radix 1.8 stays near 0.45 LSB rms with only about 2 % off. Switch the noise off and convert again: now radix 1.8 is slightly worse, 0.36 against 0.29 LSB rms, because its steps do not add up to whole codes and the sum must be rounded. Redundancy pays only when decisions can go wrong.
